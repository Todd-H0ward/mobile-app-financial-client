# Игровой период

Центральная сущность игры. Вся экономика пересчитывается **по завершении
периода**, а не по реальному времени.

Это замена прежней модели «шкалы падают по часам». Реальное время осталось, но
стало вторичным: оно красит комнату и ставит метки в истории кошелька, а
деньги, рост и итоги считает только период — и только по действию ребёнка
(0.3-R).

## Конечный автомат

```
ПЛАНИРОВАНИЕ ──► ПЕРИОД ──► ИТОГИ ──► ПЕРЕСЧЁТ ──┐
     ▲                                            │
     └────────────────────────────────────────────┘
```

| Фаза | Что делает ребёнок | Что делает приложение |
| --- | --- | --- |
| `planning` | Распределяет сумму по трём направлениям | Контролирует непревышение, показывает остаток |
| `active` | Выполняет задания, покупает, откладывает | Копит факт по тем же трём направлениям |
| `summary` | Смотрит «план vs факт» | Считает расхождения и объясняет каждое |
| пересчёт | — | Начисляет рост, обновляет стадию, готовит следующий период |

Переходы — единственный способ сменить фазу; экран не меняет состояние напрямую.

**Пересчёт — это шаг, а не фаза.** Его целиком выполняет `endPeriod` (бывший
`acknowledgeSummary`), переводя автомат из `summary` сразу в `planning`
следующего периода. Поэтому `PeriodPhase` состоит ровно из трёх значений:
состояния «между периодами» не существует, и сейв не может его хранить.
`settlement` в типе фазы нет намеренно — это значение никогда не было бы
достижимым, зато каждый `switch` по фазе был бы обязан его обрабатывать.

## Период завершается кнопкой, а не календарём

ТЗ оставляет продолжительность периода и его привязку к реальному времени на
усмотрение команды. Мы делаем период **завершаемым явным действием**:
«Завершить день» на главном экране → экран подтверждения → итоги.

Почему так:

- демо-режим обязан прогонять 5 периодов подряд без ожидания реального времени
  (2.5.13) — с календарной привязкой это невозможно;
- эксперт на защите должен пройти весь цикл за минуты;
- ребёнок видит причинно-следственную связь сразу, а не через сутки;
- исчезает целый класс багов с часовыми поясами, переводом часов и
  «отмоткой времени назад»;
- закрытие приложения на любой срок **не меняет** состояние питомца.

### Кнопка в HUD — три состояния

| Состояние | Когда | Поведение |
| --- | --- | --- |
| `disabled` | нет подтверждённого плана (`planning` / пустой план) | кнопка недоступна |
| `ready` | `active` и факт нужного ≥ плана | обычный акцент |
| `warn` | `active`, но нужное ниже плана | мягкое предупреждение, **не блокирует** |

Экран `/end-period` повторяет мягкое предупреждение и всегда позволяет
завершить день. Дальше: `finishPeriod` → `summary` → recovery → `endPeriod`.

### Что делает `endPeriod`

Одним шагом, без часов:

1. квитанция отопления (`buildBill` → debit + `fact.needs`, без минуса);
2. деградация comfort / spirit по таблице `PERIOD_NEED_DECAY`;
3. строка истории, бонус регулярности, рост питомца, сброс плана/факта/заданий,
   `index++`, фаза → `planning`.

## `TimeSource` — метки, не экономика

Ни один модуль не вызывает `Date.now()` напрямую. Время приходит из
`TimeSource` и нужно только для меток кошелька / контента:

```ts
interface TimeSource {
  /** Текущий момент, мс эпохи. */
  now: () => number;
}
```

Движок периода **не читает** `TimeSource`. `startPeriod` / `finishPeriod` /
`endPeriod` принимают опциональный `at` только чтобы тесты и демо ставили
упорядоченные метки истории (`phaseEnteredAt` / `endedAt`). В проде вызывают
без аргумента — счётчик берётся из сейва.

Провайдер всегда отдаёт `realTimeSource`. Демо-режим больше не подменяет часы.

## Демо-режим

Требование 2.5.13, оценивается отдельно. Управление — в карточке «Демо-режим»
(`features/demo-mode`); позже переедет за арифметический барьер.

- тестовый профиль с предзаполненным состоянием (`createDemoProfile`);
- **профиль ребёнка не стирается**: при включении демо он паркуется в
  `demoBackup` (`enterDemoMode`), при выключении возвращается ровно таким, каким
  был (`exitDemoMode`);
- сброс к исходному состоянию одной кнопкой;
- **5 периодов подряд** кнопкой «Прогнать 5 периодов» без ожидания реального
  времени (`runDemoPeriods`) — чистый прогон FSM, без `DemoTimeSource` и без
  `tick()`;
- прогон подставляет фиксированный план по трём направлениям; **факт остаётся
  нулевым**, пока нет покупок и заданий в демо-сценарии;
- все задания обязательного сценария доступны сразу.

Демо-режим не «ускоряет» игру и не подменяет формулы — это тестовый профиль
плюс сброс и прогон автомата. Иначе демонстрация показывает не то приложение,
которое сдаётся.

## Нет состояния провала

ТЗ (2.2) запрещает давление и обнуление прогресса, поэтому:

- период нельзя «проиграть» — итоги показывают расхождение плана и факта, а не
  оценку;
- ошибка не обнуляет накопления и не откатывает стадию питомца;
- после неудачного периода экран итогов предлагает **путь восстановления**:
  что именно можно сделать в следующем периоде, чтобы выправить положение;
- стадии роста никогда не идут назад.

Расхождение — это материал для объяснения, а не повод для наказания.

## Что хранится

Состояние периода — часть профиля, см. [game-state.md](./game-state.md):

```ts
interface PeriodSave {
  /** Номер периода, с 1. Растёт монотонно, не сбрасывается. */
  index: number;
  /** Текущая фаза автомата. Ровно три: пересчёт — шаг, а не состояние. */
  phase: 'planning' | 'active' | 'summary';
  /** План на период: сколько ребёнок выделил по каждому направлению. */
  plan: BudgetPlan;
  /** Факт за период: сколько реально ушло по каждому направлению. */
  fact: BudgetFact;
  /** Метка входа в текущую фазу (монотонный счётчик / тест-штамп). Для истории, не для расчётов. */
  phaseEnteredAt: number;
}
```

`phaseEnteredAt` используется только в истории и в разделе для взрослого. На
деньги и рост он не влияет — иначе изменение системных часов стало бы способом
получить выгоду.

## Тесты

Пункты, которые должны быть закрыты автотестами:

- автомат не пропускает фазы и не выходит за пределы трёх состояний;
- из `summary` всегда получается корректный `planning` следующего периода;
- `endPeriod` применяет `PERIOD_NEED_DECAY` и квитанцию отопления за период;
- `isPlanKept` считает нарушением перерасход по **любому** направлению, включая
  те, куда не выделено ничего: потратить там, где план нулевой, — самое явное
  нарушение плана, а не исключение из проверки;
- демо-режим прогоняет 5 периодов подряд и оставляет профиль в валидном виде;
- выход из демо-режима возвращает профиль ребёнка целиком, вместе с именем,
  питомцем и балансом;
- расчёты периода не зависят от `Date.now()` / `TimeSource.now()`.
