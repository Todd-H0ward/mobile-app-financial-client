# Игровой период

Центральная сущность игры. Вся экономика пересчитывается **по завершении
периода**, а не по реальному времени.

Это замена прежней модели «шкалы падают по часам». Реальное время осталось, но
стало вторичным: оно красит комнату и подбирает реплику, а деньги, рост и итоги
считает только период.

## Конечный автомат

```
ПЛАНИРОВАНИЕ ──► ПЕРИОД ──► ИТОГИ ──► ПЕРЕСЧЁТ ──┐
     ▲                                            │
     └────────────────────────────────────────────┘
```

| Фаза | Что делает ребёнок | Что делает приложение |
| --- | --- | --- |
| `planning` | Распределяет сумму по трём направлениям | Контролирует непревышение, показывает остаток |
| `active` | Выполняет задания, покупает, откладывает | Копит факт по тем же трём направлениям |
| `summary` | Смотрит «план vs факт» | Считает расхождения и объясняет каждое |
| `settlement` | — | Начисляет рост, обновляет стадию, готовит следующий период |

Переходы — единственный способ сменить фазу; экран не меняет состояние напрямую.
Из `settlement` автомат сразу входит в `planning` следующего периода, так что
«между периодами» состояния не существует.

## Период завершается кнопкой, а не календарём

ТЗ оставляет продолжительность периода и его привязку к реальному времени на
усмотрение команды. Мы делаем период **завершаемым явным действием**:
«Завершить период» на главном экране.

Почему так:

- демо-режим обязан прогонять 5 периодов подряд без ожидания реального времени
  (2.5.13) — с календарной привязкой это невозможно;
- эксперт на защите должен пройти весь цикл за минуты;
- ребёнок видит причинно-следственную связь сразу, а не через сутки;
- исчезает целый класс багов с часовыми поясами, переводом часов и
  «отмоткой времени назад».

Кнопка доступна, когда в периоде закрыт хотя бы один пункт плана — иначе
завершать нечего, и об этом прямо написано под кнопкой.

## `TimeSource` — абстракция времени с первого дня

Ни один модуль не вызывает `Date.now()` напрямую. Время приходит из `TimeSource`:

```ts
interface TimeSource {
  /** Текущий момент, мс эпохи. */
  now: () => number;
}
```

Номер текущего периода живёт в сейве (`user.period.index`), а не в часах —
время отвечает только за метки `phaseEnteredAt` / `endedAt` в истории.

Две реализации:

| Реализация | Где | `now()` |
| --- | --- | --- |
| `realTimeSource` | обычная игра | системные часы |
| `demoTimeSource` | демо-режим | управляемый счётчик, шагает по `tick()` |

Это не «сделаем в конце». Демо-режим — оцениваемое требование, и он влияет на
архитектуру времени с первого дня: модуль, написанный на `Date.now()`, в
демо-режиме не прогоняется, и переписывать его придётся вместе с тестами.

**Правило:** `Date.now()` допустим только внутри `realTimeSource`. Всё остальное
получает время параметром или через провайдер.

## Демо-режим

Требование 2.5.13, оценивается отдельно. Пока раздела для взрослого нет,
управление лежит в карточке «Демо-режим» на главном экране
(`features/demo-mode`); позже переедет за арифметический барьер.

- тестовый профиль с предзаполненным состоянием (`createDemoProfile`);
- сброс к исходному состоянию одной кнопкой («Сбросить к исходному»);
- **5 периодов подряд** кнопкой «Прогнать 5 периодов» без ожидания реального
  времени (`runDemoPeriods` + `demoTimeSource.tick`);
- прогон подставляет фиксированный план по трём направлениям; **факт остаётся
  нулевым**, пока нет кошелька, заданий и магазина — подрисовывать расходы
  было бы враньём про движок;
- все задания обязательного сценария будут доступны сразу, без разблокировки
  (когда появится каталог заданий).

Демо-режим не «ускоряет» игру и не подменяет формулы — он подменяет только
`TimeSource` и стартовый профиль. Иначе демонстрация показывает не то
приложение, которое сдаётся.

## Нет состояния провала

ТЗ (2.2) запрещает давление и обнуление прогресса, поэтому:

- период нельзя «проиграть» — итоги показывают расхождение плана и факта, а не
  оценку;
- ошибка не обнуляет накопления и не откатывает стадию питомца;
- после неудачного периода экран итогов предлагает **путь восстановления**:
  что именно можно сделать в следующем периоде, чтобы выправить положение;
- стадии роста никогда не идут назад.

Расхождение — это материал для объяснения, а не повод для наказания.

## Что хранится

Состояние периода — часть профиля, см. [game-state.md](./game-state.md):

```ts
interface PeriodSave {
  /** Номер периода, с 1. Растёт монотонно, не сбрасывается. */
  index: number;
  /** Текущая фаза автомата. */
  phase: 'planning' | 'active' | 'summary' | 'settlement';
  /** План на период: сколько ребёнок выделил по каждому направлению. */
  plan: BudgetPlan;
  /** Факт за период: сколько реально ушло по каждому направлению. */
  fact: BudgetFact;
  /** Момент входа в текущую фазу, мс эпохи. Для истории, не для расчётов. */
  phaseEnteredAt: number;
}
```

`phaseEnteredAt` пишется из `TimeSource.now()` и используется только в истории и
в разделе для взрослого. На деньги и рост он не влияет — иначе изменение
системных часов стало бы способом получить выгоду.

## Тесты

Пункты, которые должны быть закрыты автотестами:

- автомат не пропускает фазы и не выходит за пределы четырёх состояний;
- из `settlement` всегда получается корректный `planning` следующего периода;
- демо-режим прогоняет 5 периодов подряд и оставляет профиль в валидном виде;
- ни один расчёт не зависит от `Date.now()` — проверяется подстановкой
  `demoTimeSource` со сдвинутым временем: результаты обязаны совпасть.
