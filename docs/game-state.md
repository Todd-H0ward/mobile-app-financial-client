# Состояние, сохранение и время

Одно сохранение и один источник времени. Всё остальное читает их через
публичный API слайса.

Прежняя модель «шкалы падают по реальному времени» больше не является основой:
экономику считает период, см. [game-period.md](./game-period.md). Реальное время
осталось только как оформление.

## Профиль

Требование 2.5.13: состояние сохраняется между запусками. Профиль **локальный и
гостевой** — ни аккаунта, ни регистрации, см. [privacy.md](./privacy.md).

```ts
interface UserSave {
  /** Версия схемы. Растёт при каждом несовместимом изменении. */
  version: number;
  /** Игровое имя ребёнка. Задаётся в онбординге, 2.5.1. */
  playerName: string;
  /** Момент создания профиля, мс эпохи. Для раздела взрослого. */
  createdAt: number;
  /** Питомец: вид, окрас, узор, имя, черты, стадия. */
  pet: PetSave;
  /** Кошелёк: баланс и последние 100 операций с источником и суммой. */
  wallet: WalletSave;
  /** Копилка: цели и отложенное по каждой. */
  savings: SavingsSave;
  /** Текущий период: фаза, план, факт. См. game-period.md. */
  period: PeriodSave;
  /** Завершённые периоды: план, факт и итоги каждого. Для истории, 2.5.11. */
  history: PeriodRecord[];
  /** Дом: температура, купленные утепления, мебель. */
  home: HomeSave;
  /** Что настроил взрослый: барьер, звук, анимации, демо-режим. */
  settings: SettingsSave;
}
```

Каждое поле снабжено комментарием — это правило AGENTS.md для сторов и сейвов:
сейв читает тот, кто будет его отлаживать через год.

## Хранилище

| Что | Где |
| --- | --- |
| Схема | `entities/user/model/types.ts` |
| Стор | `entities/user/model/store/` — zustand + `persist` |
| Носитель | `expo-sqlite/kv-store` через `shared/model/persist-storage`, один ключ `@app:user` (`STORAGE_KEYS.USER`) |
| Стартовый профиль | `entities/user/model/initial-user/` — `createInitialUser` |
| Миграции | `entities/user/model/migrations/` — `USER_SAVE_VERSION` + `migrateUser` |
| Сброс | `entities/user/lib/reset/` — `resetUser` |

- **Автосохранение** — это middleware `persist`: каждый `set` пишет сейв, так
  что явного «сохранить» нет и терять на падении нечего.
- **`partialize`** держит действия и временные флаги вне файла — пишутся ровно
  два поля: `user` и `demoBackup`.
- **`demoBackup` — припаркованный сейв ребёнка на время демонстрации.** Включение
  демо-режима не стирает профиль: он кладётся сюда и возвращается целиком, когда
  демо выключают. Поле персистится, потому что демонстрация может пережить
  перезапуск приложения. Читается тем же `isUserSave`, что и основной сейв:
  битая парковка стоит только припаркованного профиля, но не запуска.
- **Чтение синхронное, и это архитектурное решение.** `expo-sqlite/kv-store`
  умеет `getItemSync`, поэтому `persist` гидратируется в том же тике, в котором
  создан стор: на первом же кадре `user === null` значит «профиля нет», а не
  «ещё не загрузился». Флага `hasHydrated`, ожидания на старте и гейта над
  навигацией в проекте нет — их и нечего забыть проверить в новом экране.
  С обычным AsyncStorage каждый экран, читающий сейв, обязан был бы ждать флаг.
- **Куда пускать на старте, решает роутер.** `screens/entry` — единственное
  место с этой веткой: есть профиль — `/home`, нет — `/onboarding`.
  Старт укладывается в бюджет ≤ 5 с, см. [performance.md](./performance.md).
- **В ключе нет версии приложения.** Ключ вида `@app:user:${APP_VERSION}` —
  это обновление, молча стирающее данные. Изменения схемы идут через
  `version` + `migrate`, никогда через новый ключ.
- **Миграции** идут по шагу (`v0 → v1 → …`), поэтому игрок, пропустивший три
  релиза, доезжает до текущей схемы. Нечитаемые данные дают чистый профиль, а не
  падение на запуске.

Изменить схему: правим `UserSave`, поднимаем `USER_SAVE_VERSION`,
добавляем шаг в `migrateUser`, покрываем в `migrations.test.ts`.

## Время

Ни один модуль не вызывает `Date.now()` напрямую — время приходит из
`TimeSource`. Полностью описано в
[game-period.md](./game-period.md#timesource--абстракция-времени-с-первого-дня).

Коротко: две реализации (реальная и демо-режима), и ни один расчёт денег или
роста не зависит от системных часов. Перевод часов не может стать выгодой, а
демо-режим прогоняет 5 периодов подряд без ожидания.

## Сброс и удаление профиля

Требование 2.5.12, доступно из раздела для взрослого.

| Действие | Что делает |
| --- | --- |
| **Сброс к исходному состоянию** | Возвращает профиль к стартовому: баланс, копилка, дом, история, период 1, стадия питомца. Переживают сброс имя ребёнка, внешность и имя питомца и настройки взрослого — это не прогресс |
| **Удаление профиля** | Стирает ключ `@app:user` целиком; приложение открывается с онбординга |
| **Выключение демо-режима** | Возвращает припаркованный профиль ребёнка как он был. Это не сброс: демонстрация не стоит ребёнку ни монеты. Парковки нет — выдаётся чистый стартовый профиль, но никогда демошный |

Оба — с подтверждением, на котором написано последствие. Удаление необратимо, и
об этом сказано прямо.

## Тесты

Покрывается чистая логика, без React Native:

```bash
pnpm test
```

- каждый шаг миграции по отдельности и цепочка целиком;
- нечитаемый сейв даёт чистый профиль, а не исключение;
- сброс возвращает ровно стартовое состояние;
- выключение демо-режима возвращает профиль ребёнка целиком, в том числе после
  перезапуска, и никогда не оставляет демошное имя;
- удаление не оставляет ключей в хранилище;
- расчёты не зависят от системных часов — проверяется подстановкой
  `demoTimeSource` со сдвинутым временем.
