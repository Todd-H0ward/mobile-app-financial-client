# Вёрстка под разные размеры

Приложение должно нормально выглядеть на телефонах и планшетах. Достигается это
**не масштабированием пикселей**, а гибкой вёрсткой.

## Адаптивного масштабирования больше нет

Раньше в проекте был слой `scale()` / `fontSize()` / `useResponsive()`, который
пересчитывал размеры из макета 375×812 в точки устройства. Он **удалён
намеренно**: размеры в ките — это обычные точки дизайна.

Не ищите примитивы `vw` / `vh` / `moderateScale` / `select` — их нет нигде.
В `@/shared/utils` лежат чистые хелперы (`clamp`, `formatMoney`, `hitSlopFor`),
в `@/shared/lib` — инфраструктура, зависящая от React (сейчас только
`time-source`). Коэффициента размера нет ни там, ни там.

Причины отказа:

- масштабирование каждого числа делает планшет зумом телефона, а не более
  просторной раскладкой — то есть решает не ту задачу;
- умножение всех размеров ломает пиксельную сетку и делает границы и скругления
  нестабильными;
- реальную разницу между телефоном и планшетом решают flex, перенос строк и
  ограничение ширины колонки, а не коэффициент.

## Чем пользоваться вместо

| Задача | Инструмент |
| --- | --- |
| Отступы | `SPACING` из `@/shared/constants` |
| Боковые поля страницы | `CONTENT_PADDING` |
| Ширина читаемой колонки | `MAX_CONTENT_WIDTH` — `Screen` применяет сам |
| Растянуть по доступному месту | `flex`, `alignSelf: 'stretch'`, `width: '100%'` |
| Раскладка, зависящая от ширины | перенос через `flexWrap`, а не расчёт по ширине экрана |
| Действительно нужна ширина окна | `useWindowDimensions()` из `react-native` |

`Screen` уже держит фон, safe area, скролл и колонку, ограниченную
`MAX_CONTENT_WIDTH`. На планшете колонка остаётся по центру, а не растягивается
на весь экран — этого достаточно для одноколоночных экранов, которых в игре
большинство.

## Правила

1. Отступ — из `SPACING`. Поля страницы — `CONTENT_PADDING`.
2. Фиксированный размер (иконка, скругление, высота плитки) — обычное число
   в точках дизайна, без обёртки.
3. Пропорциональный размер — через `flex`, а не через проценты от экрана.
4. Разная структура на телефоне и планшете — `useWindowDimensions()` в
   компоненте, не `Dimensions.get()` на модульном уровне: второе не переживает
   поворот и разделённый экран.
5. Нижняя граница текста и целей нажатия — в
   [accessibility.md](./accessibility.md), и она важнее любой адаптивности.

## Проверка

UI-кит (`/ui-kit`) — самый длинный и самый плотный экран в приложении. Если он
проходится без горизонтального скролла и без обрезанных подписей на телефоне
375pt и на планшете, вёрстка кита в порядке.
