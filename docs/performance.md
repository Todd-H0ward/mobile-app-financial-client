# Производительность

Требование 3.7, проверяемое на устройстве: **старт ≤ 5 секунд, отклик ≤ 1
секунда** на устройстве от 3 ГБ оперативной памяти.

## Риск стека

React Native с холодным стартом на слабом Android — риск ровно по этому пункту.
Стек по ТЗ свободный; если в команде нет опыта оптимизации RN, Kotlin + Compose
безопаснее. Решение принимается осознанно и один раз — переезд на волне 2 не
состоится.

Раз выбран RN, меры ниже обязательны, а не «если останется время».

## Старт ≤ 5 секунд

| Мера | Почему |
| --- | --- |
| Hermes включён | байткод вместо парсинга JS при запуске |
| Релизная сборка для замеров | dev-сборка стартует в разы дольше и меряет не то |
| Минимум работы до первого кадра | профиль читается синхронно; измеряем время чтения ограниченного save |
| Ничего тяжёлого в модульной области | `Dimensions.get()` и подобное на старте — норма, парсинг JSON контента — нет |
| Контент грузится по требованию | `content/*.json` нужен на своём экране, а не при запуске |
| Шрифт один | каждый забандленный шрифт — это байты и кадр задержки |

**React Compiler выключен** (`app.json → experiments.reactCompiler: false`) — он
ломает worklets Reanimated в этом проекте, см. AGENTS.md. Это не про скорость, но
включение ради оптимизации уронит приложение.

## Отклик ≤ 1 секунда

| Мера | Почему |
| --- | --- |
| Анимации на UI-потоке | Reanimated shared values — JS-поток не участвует в кадре |
| Никаких пересчётов в worklet | worklet вызывает только worklet, см. AGENTS.md |
| Сохранение не блокирует ввод | запись профиля синхронна ради сохранности; измеряем задержку на устройстве, не сохраняем покадровое состояние |
| Списки виртуализируются | каталог и история — `FlatList`, не `map` в `ScrollView` |
| Не больше одного анимированного персонажа на экране | три анимированных аватара — то, что заикается |

## Как меряется

Замеры на **физическом устройстве** от 3 ГБ, в **релизной** сборке, после
холодного запуска (приложение выгружено из памяти).

```bash
# Холодный старт, Android
adb shell am force-stop <package>
adb shell am start -W -n <package>/.MainActivity
# TotalTime в выводе — это и есть время старта
```

Отклик меряется секундомером по сценарию: нажатие «Подтвердить план» →
появление главного экрана; нажатие на позицию каталога → появление
подтверждения.

Результаты прикладываются к пакету сдачи (шаг 36 в
[roadmap.md](./roadmap.md#волна-3--сдача)).

## Замеры — 28.09.2026

Nokia 8 (TA-1004): Android 9, Snapdragon 835, 4 ГБ RAM, 1440×2560. Релизный
вариант (`expo run:android --variant release`, отладочная подпись — для
замеров, не для сдачи). Кадры — `dumpsys gfxinfo` за 5 с: сцена рисуется в
`TextureView` внутри окна, поэтому кадры окна — это кадры сцены.

| Что | Результат |
| --- | --- |
| Старт до первого кадра окна (`am start -W`) | ~2,5 с |
| Старт до экрана, на который можно нажать | ~4–5 с: заставка → белая вспышка ~1 с → знакомство |
| Загрузка арены после знакомства | несколько секунд под экраном «поднимаю арену» |
| Память на главном экране | ~310 МБ (отладочная сборка — ~870 МБ) |

Главный экран в покое, до и после ограничения частоты кадров сцены в покое
(`IDLE_FPS` в `widgets/room-scene/ui/room-scene.tsx`):

| | 60 кадров/с всегда | 30 кадров/с в покое |
| --- | --- | --- |
| Кадры окна в секунду | ~42 | ~26 |
| Процессор, весь процесс | ~200% | ~116% |
| JS-поток (`mqt_v_js`) | ~102% | ~94% |
| Поток GL / RenderThread | ~44% / ~38% | ~15–21% / ~12% |

Ограничение почти вдвое снижает общую нагрузку (нагрев, батарея), но JS-поток
остаётся занят почти полностью.

### Из чего состоит кадр

Профиль через DevTools снять не удалось: отладочный сокет Metro закрывался
(1006) и у встроенного React Native DevTools тоже. Поэтому цикл кадра разметили
временными замерами (`performance.now()` вокруг частей кадра, отладочная
сборка):

| Часть кадра | Время |
| --- | --- |
| Камера, подъём, фокус (до `tick`) | ~0,3 мс |
| `built.tick` — анимации робота, дымки, Смотрителей | ~0,5 мс |
| `webgl.render` | **~33,5 мс** |
| `gl.endFrameEXP` | ~0,1 мс |

`webgl.info` за кадр: **289 вызовов отрисовки**, ~92 тыс. треугольников,
270 геометрий, 6 текстур, 11 шейдерных программ. Треугольников для
Snapdragon 835 немного; дорого число вызовов — three.js выдаёт на каждый
десятки GL-команд, и каждая идёт через JSI expo-gl на JS-потоке.

Откуда вызовы: арена (90 клеток, цифры, кольца) — около 40, её геометрия уже
слита. Остальное — модели: робопёс собран из десятков мелких мешей
`MeshStandardMaterial` на суставах (корпус ~60, голова ~55, лапы по несколько
на сустав), Смотрители — ещё несколько десятков.

Что сократит JS-время кадра, по отдаче:

1. **Слить меши робота внутри одного сустава с одним материалом** — при
   конвертации модели или при загрузке. Анимация суставов сохраняется, а
   вызовов становится в разы меньше.
2. **То же для Смотрителей**: у них почти нет анимации частей, их можно слить
   до нескольких мешей.
3. Смотрителям вдали хватит `MeshLambertMaterial` вместо PBR.

Белая вспышка при старте, блокировка JS на ~2,5 с при сборке сцены и время
загрузки арены — отдельные задачи на 3.7.
