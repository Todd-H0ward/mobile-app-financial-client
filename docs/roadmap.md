# План работ

Четыре волны. Волна 3 идёт **параллельно** первой, а не после неё: пакет
документации по объёму сопоставим с неделей разработки, и в хакатонах его
теряют вместе с баллами.

## Волна 0 — фундамент

Без этого поедет всё остальное, поэтому делается первым и целиком.

1. Каркас проекта и **сборка подписанного релизного APK с первого дня**.
   Это отдельная боль (ключи, `expo prebuild`, профили EAS), и откладывать её
   до сдачи — самый дорогой способ потерять полдня. — 3.3
2. Локальное хранилище, модель профиля, сохранение и восстановление. — 2.5.13
3. **Движок игрового периода**: конечный автомат, абстракция времени
   `TimeSource`, переключатель демо-режима. — [game-period.md](./game-period.md)
4. Разделение слоёв: экономика / учебный контент в JSON / хранилище / UI. — 3.4, 2.5.14
5. Дизайн-система с соблюдением 48dp и 16sp. — 3.6 *(кит готов; звук/анимации и device-чек — с родителями)*

## Волна 1 — обязательный сценарий целиком

Шаги 1–12 приложения А ТЗ. Ничего из корзины B до конца этой волны не трогать.

6. Онбординг и локальный профиль
7. Создание питомца, ≥9 различимых комбинаций
8. Главный экран со всеми обязательными элементами одновременно
9. Начисление валюты с источником и суммой
10. **Экран плана бюджета**: три направления, остаток, подтверждение
11. Каталог покупок, ≥8 позиций, блокировка при нехватке средств с объяснением
12. Цели и накопления, ≥3 цели, подтверждение снятия с показом последствий
13. **Экран итогов периода: план vs факт**
14. Движок заданий + 6 заданий по 3 темам
15. Обратная связь и путь восстановления
16. Стадии развития питомца (≥3) с объяснением причины
17. История и справочник терминов
18. Раздел для взрослого + сброс и удаление профиля
19. Демо-режим: 5 периодов подряд

> **Контрольная точка.** Обязательный сценарий проходится целиком на физическом
> устройстве. До этого момента корзина B не начинается.

### К промежуточной сдаче

Три ключевых экрана — создание питомца (7), главный (8), бюджет и
накопления (10, 12) — плюс таблица статусов из
[requirements-matrix.md](./requirements-matrix.md). То есть волна 0 и шаги
7, 8, 10.

## Что делать прямо сейчас

1. **Зафиксировать состав игрового периода** — это разблокирует всю остальную
   архитектуру.
2. Завести матрицу соответствия как живой документ — сделано,
   [requirements-matrix.md](./requirements-matrix.md).
3. **Проверить лицензию avatar lab** до того, как строить на нём арт-пайплайн.
   Если лицензия не позволяет использование в составе прототипа — весь арт
   питомца придётся переделывать, и узнать это нужно сейчас, а не на волне 2.
4. Переписать бриф для дизайнера: в прошлой версии нет экрана плана бюджета и
   экрана итогов «план vs факт» — двух самых важных экранов по ТЗ.

## Риск, который стоит решить осознанно

Требование 3.7 — старт ≤5 с и отклик ≤1 с на устройстве от 3 ГБ. React Native с
холодным стартом на слабом Android — риск ровно по этому пункту. Если в команде
нет опыта оптимизации RN, Kotlin + Compose безопаснее. Стек по ТЗ свободный,
требование — проверяемое. Меры для текущего стека собраны в
[performance.md](./performance.md).
