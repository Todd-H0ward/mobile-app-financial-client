# Робопёс

Персонаж игры — робособака на платформе на дне ямы. Код — `entities/robot-dog`
(лист: без стора, без импортов из соседних сущностей), сохранение —
`UserSave.robot`. Сцена — [scene.md](./scene.md).

Старый концепт домашнего питомца (вид, окрас, узор, черты характера, 2D-риг,
дом с отоплением) удалён целиком. Здесь описано только то, что перешло в новую
игру. Правила подъёма платформы и модулей ещё не утверждены — см.
`output/planning/`.

## Сохранение

```ts
interface RobotSave {
  name: string;        // пусто, пока знакомство не спросило имя
  stage: RobotDogStage; // 'basic' | 'upgraded' | 'complete', только вверх
  charge: number;      // заряд, 0…1 — обеспеченность нужного
  spirit: number;      // настроение, 0…1 — цель, задания, итог периода
}
```

Внешность — `settings.robotSkin` (семь окрасов), поведение по умолчанию —
`settings.robotAction`. Купленные вещи, которые остаются (консоль, пазлы), —
`UserSave.ownedItemIds`: по ним открываются мини-игры.

## Стадии сборки (ТЗ §2.6 — три стадии)

Стадия — не покупка, а итог серии решений за несколько периодов (§2.5.10).
`growRobotDog` пересчитывает её при закрытии периода по истории:

| Стадия | Периодов | Достигнутых целей | Соблюдённых планов |
| --- | ---: | ---: | ---: |
| `basic` | 0 | 0 | 0 |
| `upgraded` | 2 | 1 | 1 |
| `complete` | 4 | 2 | 3 |

- Ожидание — не условие: каждый счётчик — решение ребёнка.
- Стадия никогда не понижается (§2.2): ошибка не отнимает прогресс.
- `progressToNextStage` называет, чего не хватает, целыми числами — это
  показывает взрослый раздел.

Числа — рабочее предложение, их согласуют вместе с экономикой.

## Настроение (§2.5.10 — причина объясняется)

Две оси дают пять состояний, у каждого есть причина (`moodFor`):

| Состояние | Когда | Клип робособаки |
| --- | --- | --- |
| `proud` | обе оси ≥ 0.7 | `joy` |
| `content` | середина | `idle` |
| `bored` | низкое настроение | `walk` |
| `tired` | низкий заряд | `sad` |
| `sad` | обе оси низкие | `sad` |

Причины — `charged`, `drained`, `goal-near`, `goal-far`, `tasks-done`,
`plan-kept`, `plan-broken`, `nothing-to-do`; тексты — `robot.reason.*` в
локалях. Заряд растёт от покупок нужного (`chargeDelta` в каталоге), настроение —
от заданий; при закрытии периода обе оси падают на `PERIOD_NEED_DECAY`. Никаких
поломок, болезней и потери прогресса от нуля заряда.

## Имя

`normalizeRobotName` / `validateRobotName`: до 10 символов, минимум один.
Второе после имени игрока поле свободного ввода, никуда не отправляется —
[privacy.md](./privacy.md).
